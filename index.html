QA / SDET Prep

The Free Self-Study Path

Everything below is free. Work top to bottom, check things off as you go, and build the capstone project last — it's what actually proves you can do the job.

0 of 0 done
01

Programming Basics

Get comfortable writing and reading code before you automate anything.

  • Java Programming MOOC — University of Helsinki
    Free, structured, exercise-heavy. Good if your team's stack is Java/Selenium.
  • Official Python Tutorial — python.org
    Pick Java or Python based on what your target company uses — don't learn both at once.
02

Testing Fundamentals

Vocabulary and concepts — what interviewers actually probe for.

  • Test Automation University (Applitools)
    Free courses on testing, automation, and frameworks.
  • ISTQB Foundation Syllabus
    Free PDF. Read it for the concepts and terminology — skip the certification exam unless a job specifically asks for it.
03

UI Automation

Learn one tool deeply rather than skimming three.

  • Selenium — official documentation
  • Playwright — official documentation
    One of the best tool docs out there — a strong default choice in 2026.
  • SauceDemo · The Internet · Automation Exercise
    Practice sites built specifically for automating against.
04

API Testing

Most real-world test suites are API-heavy — don't skip this for UI automation alone.

  • Postman Academy
  • Restful Booker · ReqRes · JSONPlaceholder
    Free practice APIs — build real request/response test cases against these.
05

SQL for Testers

You will be asked to verify data in a database. Get fluent.

  • SQLBolt
    Interactive basics.
  • LeetCode SQL 50
    Practice set once the basics are solid.
06

CI/CD

A test suite nobody runs automatically doesn't count.

  • GitHub Skills
    Hands-on Git and GitHub Actions courses, free.
  • GitHub Actions — official documentation
07

Capstone: Put It All Together

This single project will do more for your interviews than any certificate on this page.

  1. Pick one practice site from Module 3.
  2. Build a framework with page objects and a config layer.
  3. Add API tests against one of the practice APIs from Module 4.
  4. Wire it up to run on GitHub Actions on every push.
  5. Write a README that explains every decision you made and why.
The honest part. These resources teach you what to learn. They won't look at your gaps, tell you why your interview answers sound weak, or keep you accountable when you want to quit. Treat this page as the syllabus — pair it with real mock interviews and code review from someone further along.
